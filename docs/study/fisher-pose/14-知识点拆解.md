# 姿势调节：学到什么，不能误学什么

来源：[逐段走读](08-逐段源码走读.md)。固定版本、精确覆盖见[阅读总览](00-阅读总览.md)。这是学习结论，不是已实现的MotionDeck功能清单。

| 知识点 | 解决的问题 | 源码落点 | 需要记住的边界 |
| --- | --- | --- | --- |
| 操作意图仲裁 | 一个手势不同时摆骨和转镜头 | 核心1853；适配1223；移动工具10–30 | 捕获阶段、命中轴优先、工具互斥共同作用 |
| 固定深度平面及点击偏移 | 开始拖动不突然跳位 | 核心1935–1950、2137–2180 | 单视图只确定平面内位置，前后深度要换视角或明确轴 |
| FK/IK协作 | 大致摆位置后再精调朝向 | 核心537、2303；旋转控件520 | 位置、弯曲方向、末端朝向不是同一个约束 |
| 当前弯曲方向作提示 | 减少无缘由翻肘/翻膝 | 核心576–591、983–1002 | 接近伸直仍有退化；不等于生理关节限位 |
| 独立腕部及手掌坐标系 | 解决掌心/虎口和武器轴向 | 核心6570–6622；适配1354 | 导入有方向基准，手动IK没有自动掌向约束；手腕点不足以确定朝向 |
| 手指预设和连续握紧 | 不必逐根手指从零摆 | 手势数据全文；核心4003–4203 | 配套骨架数据，不含腕骨，不自动贴合剑柄 |
| 从手势起点计算 | 避免重复叠加、保持可撤销 | 旋转控件257–263、520–529；适配1327 | 参考实现的所有入口并未统一事务，不应盲目复制 |
| 一份骨架为真值 | IK/FK切换后目标不漂移 | 核心2892、适配1359 | 正在拖的目标不能被旧骨位置反写 |
| 按逻辑身份恢复选中 | 模型刷新后不抓旧骨对象 | 核心3024–3088 | 同名骨存在是必要条件，不意味着跨骨架语义兼容 |
| 绑定姿态与当前姿势分离 | 避免改身材后蒙皮抵消/错位 | 核心3183–3268 | 参考骨架的零旋转规则不可直接套给任意GLB |

## 不能照搬的五点

1. 不将几何人偶的自动拉长肢体带进固定游戏骨架。
2. 不因存在弯曲目标接口，就认为当前界面已有正常可用的控件。
3. 不把“末端算到了”或单步角度限制当作肩肘腕合理、防穿模的证明。
4. 不把旋转库自带reset当成产品已经接好Esc、cancel、失焦和撤销边界。
5. 不复制专用骨架的角度、镜像公式、零姿态和蒙皮权重到其他模型。

## 对用户“我也能上手摆”的直接回答

参考价值不止“拖手脚后旋转”：直接拖肘/膝会转父骨，手脚随动，直臂也能摆向；点手脚另走末端求解，显式弯曲目标又是独立分支。加上人体表面选骨、整链高亮、点击与拖后不同选择状态、手指预设和观察/输出镜头分工，才是面向用户的完整链。之前提炼漏掉/混淆这些关键交互，详见[本轮纠偏](15-交互语义复核与纠偏.md)。

如果后续进入实现，验收仍须用MotionDeck真实模型近景、多视角、连续拖动验证肩肘腕与表面形变。这里没有完成运行验收，也不把阅读结论当作已修好的产品。
