# 手动摆姿：入口与状态

基线及阅读覆盖见[总览](00-阅读总览.md)。以下源码行号指固定快照，不指网页解析行号。

## 入口分工

Fisher `freepose.mjs:104–126` 创建核心对象。选中变化回调更新当前骨名和三轴滑杆；姿势变化回调刷新控件及预览。`syncMode: 'end'` 表明此适配希望在交互收尾同步，具体通知实现仍需精读。

核心的手动编辑有两个相接但不同的入口：

1. 画布按下/移动/松开：`handlePointerDown` → `handlePointerMove` → `handlePointerUp`。
2. 选中后的旋转环：`selectBone` → Three.js `TransformControls` → `objectChange` / `dragging-changed`。

## 一次“拖手”的实际过程

1. 按下前更新网格和骨架世界矩阵；已有旋转轴命中则不抢操作。
2. 命中有效关节链后，保存撤销快照，建立经过被点关节、朝向观察相机的平面。
3. 保存末端与鼠标交点偏移，暂停相机，捕获指针，移除旋转环。
4. 移动时做鼠标射线和平面求交，加回偏移，写末端目标。
5. `solveIKForEffector` → `solveWithPole` → 两骨或 CCD 分支，改骨骼旋转并刷新骨架。
6. 松开清临时目标、释放捕获、恢复相机、发姿势变化通知。真正拖动后取消骨骼选择；没有被判为拖动则选骨并显示旋转环。

输入是屏幕指针及当前骨架；输出是骨骼姿势及界面反馈，不是把屏幕像素直接写进骨骼位置。

## 状态边界

| 状态 | 保存什么 | 谁更新 |
| --- | --- | --- |
| `selectedBone` | 当前旋转对象 | 选择接口 |
| `directDrag` | 链、目标、平面、偏移、起始指针、是否拖动 | 指针事件 |
| `selectedIKEffector` | 当前被求解的末端目标对象 | 移动与收尾 |
| `ikController.modes/poleModes` | 链是否启用、弯曲目标是否启用 | 模式接口 |
| `history/future` | 编辑前快照与重做状态 | 手势入口、撤销/重做 |

特别注意：移动超过3像素只修改 `hasDragged`；当前 `handlePointerMove` 并没有在未超过阈值时禁止求解。不能把它讲成完整的“3像素以内绝不改姿势”。

第二轮已补齐构造、真实事件注册、取消边界和通知实现，见[逐段走读续篇](08-逐段源码走读.md)。结论：正常up收尾链闭合；核心直接拖关节没有cancel/丢捕获收尾。它不是完整的异常生命周期示范。
