# 桌面架构与助手操作方向

2026-10-15。Electron框架选择已完成，v0.2.0纳入命令、检查、位移和AI工作区，技能独立为0.1.0。实际发布状态见[当前计划](stages/current-todo.md)；本文说明整体边界，助手操作的技术方案见[assistant-control.md](assistant-control.md)。

## 已实现基础

- Windows Electron 客户端、单实例、内部 `motiondeck://app` 资源、沙箱及上下文隔离；8901 仅是独立网页开发入口，没有云端部署。
- 一份渲染进程会话，核心/应用/平台/界面小步分层；既有采样、编排和导出算法保留。源码职责见 [project-structure.md](project-structure.md)。
- SQLite 索引与内容哈希素材、个人目录、目录设置、当前客户端旧库迁移、备份恢复，见 [data-directories.md](data-directories.md)。不访问 Chrome 或动作工坊库，不备份未保存编排。
- 当前用户安装器与受控自动更新，明确确认才重启安装；正式用户环境未由隔离发布验收自动替换。见 [install-and-update.md](install-and-update.md) 和 [verification.md](verification.md)。

不修改 action-forge/FrameDeck，不借用其依赖、进程和资料。目录分层不代表 `motion.js` 组合入口已拆净。

## 助手操作主线

目标不是继续精修界面，而是让助手通过命令操作用户正在看的模型：查询 → 动作取帧 → 批量旋转 → 多视角检查 → 撤销或确认保存 → 编排与导出。

采用本机命名管道连接已启用控制的客户端，主进程认证/路由，渲染进程应用操作层执行。界面与命令使用同一模型和事务，不在主进程复制骨架，不用DOM点击执行业务。开发脚本与A4候选包内置命令共用desktop/control/cli.cjs；内置入口通过Electron官方Node模式运行，不另外安装Node。

A2提供默认只读控制，A3姿势操作闭环和A4姿势库草稿、根骨整体变换、独立编排授权、时间轴操作与播放/保存/GLB导出纳入v0.2.0。MCP、人体约束与物理跳跃轨迹未实现。能力/限制见[命令说明](command-control.md)。没有HTTP后台、大模型账户或云服务，不让资源协议或静态服务承担任意控制；旧v0.1.1不包含这些命令能力。

## 未解决的领域问题

旧姿势编辑/全身联动实验继续隔离，实验求解器不是可靠人体约束。新姿势草稿首先保证坐标约定、完整事务、撤销和可见结果一致，再通过实际效果评估增强骨骼语义、支撑点和关节限制。

命令可以准确修改骨骼，但自然姿势仍需截图、数值检查与用户确认；传输协议跑通不等于动作质量问题解决。完整本地回归仍是发布门禁，不用旧报告或窗口启动证明新链路完成。
