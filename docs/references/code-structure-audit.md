## 第三轮：播放控制及播放栏

本段更新第二轮的“播放未完成”状态。新增application/preview-controller.js与ui/player-view.js，输入为现有会话、工作台、源动作索引和展示回调；输出为原会话变化、采样结果回调及无骨架引用的播放快照。播放栏只把点击/定位交回控制器，倍速仍写原speed控件，由原渲染循环读取，不另存速度状态。

具体流程：点击播放/重播/定位 → 控制器检查忙碌/关闭/草稿边界 → 原workbench进行非瞬态采样 → 原展示回调刷新片段与骨骼显示；每帧由入口传入wallDelta和速度，控制器沿原canAdvance检查、100毫秒上限和瞬态采样推进，播放栏刷新进度/时钟。动作不解码第二次，采样不复制，瞬态推进不增加编辑版本，失败仍由原工作台原子恢复。

状态不变式：源动作循环；编排和自定义动作停在末帧，再播放从零开始；静态姿势无编排时不切源，有编排时从轴首开始；预览定位保留上下文，时间轴定位显式进入编排。静态姿势下原进度值用time、时钟用sourceTime的历史口径也保留，不借重构修改显示语义。直接控制操作同时拒绝忙碌/草稿/关闭/无模型；界面仍保留原按钮禁用及草稿捕获隔离。

调用流程：顶部保存取帧 → 应用用例确认是否来源覆盖并绑定模型/版本 → 共用名称表单或原覆盖确认 → 原saveDraft或用户素材提交 → 原saveLibrary事务 → 成功后提交内存 → 入口刷新列表/选择和消息。输入为原state/workbench、确认函数、持久化适配和表单名称/待保存快照，输出为取消、保存结果或错误；表单不判断覆盖、不读库，不持有另一套草稿或历史。

共用表单只管理名称校验、提交锁、关闭后上下文清理及自有监听。上下文仅是待提交数据，失败仍留表单；取消不发布素材。用户用例的普通素材提交显式分成准备候选、写盘、提交内存，编码/写入失败不替换原数组和编辑ID；busy在finally恢复。草稿仍调用workbench.saveDraft，保留原授权/版本/撤销/保存边界，不另造事务。
