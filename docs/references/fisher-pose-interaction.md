## 摆姿链路

核心文件：`web/vnccs/vnccs_pose_studio_core.mjs`。

| 入口/符号 | 已确认行为 |
| --- | --- |
| `handlePointerDown`，1853行起 | 优先命中关节标记；未中时从人体表面命中点查附近骨骼。已有旋转轴命中时不抢事件。 |
| `directDrag`，1915—1966行 | 在被点关节深度建立面向观察相机的拖动平面，保存鼠标偏移、捕获指针并暂停观察相机。 |
| `handlePointerMove`，2105—2183行 | 位移超过3像素设置hasDragged，用于松开时区分选中/拖动；求解本身没有等待这一阈值。手脚拖动修改末端目标并求解；肘膝拖动则旋转父关节使中间关节跟随，并同步手脚目标。两种行为并不相同。 |
| `handlePointerUp`、`selectBone`，2232—2319行 | 未拖动的点击选关节，附着局部旋转环；拖动结束清理临时目标、恢复观察并发出姿势变化。 |
| `CCDIKSolver.solve`，710—746行 | 两骨链用解析两骨求解；手臂虽定义锁骨/大臂/前臂三骨链，但此分支明确跳过锁骨，只解最后两骨。更长链才走CCD迭代。 |
| `AnalyticIKSolver.solve2Bone`，531行起 | 读取当前骨长、限制可达距离、余弦定理解弯曲。显式弯曲目标可用；否则参考当前关节位置，避免无缘由换弯曲方向。 |
| `IKController`，893—1002行 | 默认各链为IK；显式弯曲目标默认关闭。腿在无显式目标时使用当前膝位置作方向参考。 |
| 旋转控件事件，1515—1556行 | 拖动前记录历史，拖动中更新求解/末端标记，结束同步姿势与状态。 |

手势在`web/editor/freepose.mjs`的1354—1380行附近：选中骨骼三轴旋转；手指使用预设及张手到握拳的插值滑杆。人体比例和网格来自配套MakeHuman数据，不是可直接套到任意GLB的通用绑定。

边界：本次所读求解与手动旋转链路没有完整关节生理限位或网格碰撞检测。CCD的单步45度限制不是肩/肘的最终人体角度限制。不能将演示自然推断为自动防穿模。拖肘也不能误述成“固定手腕、只改变肘弯曲方向”。

## 摄像机链路

### 独立整体移动：不是拖骨盆

2026-10-16补查：`web/editor/freepose.mjs`1083–1100的poseTool=move独立启用人物移动，1562–1573创建`movement-gizmo.mjs`控件。该模块给独立Object3D锚点挂现有TransformControls的世界坐标translate模式，暂时关闭骨关节交互；锚点从双髋中点定位，拖动增量累加到人物transform.x/y/z，再调用setActiveCharacterAppearance。核心4347–4352、4392–4402将位置写到整个skinnedMesh.position并同步目标和标记，不改关节姿态、不重解腿保脚，因此可整体腾空。

freepose1246–1269另提供Shift+左拖：按观察相机方向换算屏幕增量，但最终只写人物x/y，z保持原值，不可误称任意视角下完整屏幕平面三维拖动。手动整体摆放关闭自动构图（manualPlacement1337起），避免随后被自动适配覆盖；与仅修改拍摄镜头构图偏移、骨盆保脚均不同。以上为固定快照静态证据，未运行参考实测。MotionDeck尚无此手动整体移动入口，不应把参考工具已存在误说成需要新发明的功能。

编辑器文件：`web/editor/freepose.mjs`；核心相机：上述核心文件4637—4728行。

| 位置 | 已确认行为 |
| --- | --- |
| `setEditMode`，1069—1081行 | 明确分摆姿势/定镜头。摆姿时允许观察相机绕转，不反写已保存机位；定镜头时关闭原观察操作，改用编辑器机位参数。 |
| `setupInteraction`，1227—1245行 | 定镜头左拖修改水平/俯仰角；右键或Shift拖动改构图偏移；滚轮指数改变缩放。事件优先拦截，避免同时摆骨骼或转观察相机。 |
| `setAngle`，1059—1066行 | 改缩放或偏移即关闭自动适配，避免程序把手动特写拉回全身。 |
| `angle-from-view`，1124—1129行 | 从观察相机相对中心的方向取水平/俯仰角，应用为拍摄角度。不是完整复制观察镜头的所有内参和构图。 |
| `autoFrame`，212—251行 | 将人物投影到拍摄相机，按画面占比缩放、迭代校正中心并留边距；拖动更新约90毫秒合并，防递归适配。 |
| `updateCaptureCamera` | 独立拍摄相机保存输出比例、缩放、偏移及水平/俯仰角，同时更新可见拍摄框。 |
| `snapToCaptureCamera` | 将观察方向对齐到拍摄方向，保留视口自身视野参数，不把观察窗口与最终输出画幅混为一体。 |

## 对MotionDeck的阅读结论（非实施计划）

- 易用性来自操作分工、点击命中、拖动语义、同步反馈和历史，不是多放一个旋转环。
- 参考重点包括直接摆关节/末端、独立腕部与手势、观察与拍摄分离、手动构图优先，以及明确拍摄框。
- 现有时间轴和采样能力可继续保留，但尚未移植上述交互；当前只开放旋转仍是本项目的实际范围。
- 不直接替换骨架或混用其Three.js版本；具体适配与实现须另获用户指示，并验证本项目模型绑定、共享草稿、撤销与保存边界。
