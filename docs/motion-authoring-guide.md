# 姿势、动作制作与检查手册

适用日期：2026-10-17。面向v0.2.0客户端的38条制作/检查命令，另含未发布的3条协作会话命令（当前源码共41条）；公开v0.2.0不含新协作命令及关节约束扩展，v0.1.1不支持本机命令。协议、权限和参数限制以[本机命令说明](command-control.md)及`web/labs/motion/core/control-schema.js`为准。发布状态见[当前计划](stages/current-todo.md)。没有新增MCP或云端服务。

制作前由助手创建/选择任务，试摆与密集修帧默认`pose.save({role:'temporary',stage:'蓄力',...})`，成品动作用result。检查后只将少量可复用姿势通过`workspace.update({taskId,assetId,role:'key',stage:'蓄力',...})`推荐；短跳跃可先选约5—8个代表阶段，不把整条技术关键点链全部标key。界面只展示有效推荐与人工保留，用户逐项预览、复制或删除；临时、旧版和回收记录由助手用分页library.list查询。内部整理先workspace.cleanup预览，再以同一模型/版本确认；需保留完整过程使用keep:all，workspace.restore可恢复。完整流程与边界见[工作区说明](ai-workspace.md)。

## 手动编辑姿势（源码新增，尚未发布）

“编辑姿势”入口位于预览顶部右侧，选中态表示正在编辑。编辑时右侧展开姿势面板，占布局空间而不盖住画布；左素材库保持。面板按调整方式、关节约束、状态和撤销/重做排列，保存姿势和编辑开关统一位于预览顶部，右栏不重复显示；手部近景的选指/返回仍归编辑面板。画布与右栏底边对齐，下方播放栏横跨整个预览区。再次点击顶部编辑开关走原退出确认，退出后面板收起、画布恢复宽度；取消退出则保留草稿和面板。

观察相机：当前试用只保留人物中心观察，暂时没有模式切换入口。空白左拖绕当前观察中心旋转，滚轮远近，中键平移中心；世界竖直轴不变，上下有极点限位、不侧翻，松手停止。固定预设锁定旋转；点手掌进入近景后绕手观察，返回恢复原镜头。人物/关节/手指及环编辑优先；飞行WASD/QE、旧右键观看及锁鼠入口暂时关闭。见[相机说明](references/camera-trackball.md)。

手指：点手表面（不是腕点）放大，再点某根手指，只显示该指两个指节和指尖三点。依次拖三点只旋转近、中、远一节，上游不动、下游保持局部角度并自然跟随，不重解整指。五指统一，无手部旋转环、滑轨或预设。自然模式保留指节限位，拇指根试行少量转向联动；自由模式解除限位、不自动联动。一次拖动一步历史，Esc/失焦取消，返回全身恢复镜头；腕点和整体调整保持原语义。限位不等于防穿模，详见[手部编辑与源码依据](references/hand-editing.md)。

工具栏可选“自然约束／自由编辑”。两内置模型默认自然约束，限制本次调整的关节范围；整体平移/旋转不受人体范围限制。旋转环和拖动同帧受限，触边显示提示，反向拖立即返回。旧姿势载入/进入编辑/切换模式均不自动修正，原有超限显示数量；修改对应关节才应用范围。未标定模型明确显示“自由编辑／未标定”，不可选择自然约束。范围是工程初值，不是医学标准，也没有自动防穿模；完整配置、A1–A4边界见[关节约束实现](references/joint-constraints.md)。

身体关节点双击才打开局部旋转环，普通点击选中、拖动及松手不弹环。“整体调整”模式下，悬停人物显示手型及淡蓝高亮，点击保持选中强调，拖表面平移；双击人物才开骨盆附近的整体环，拖环旋转。点画布空白取消选择和高亮，空白拖动仍调整观察相机。键盘显式激活关节按钮仍可开环；手部继续使用三点直接拖动。高亮和开环状态不保存进姿势或导出媒体。

整体腾空：进入“编辑姿势”后，在右侧面板切“整体调整”，直接按住人物表面拖动，无需抓XYZ轴。人物沿当前观察画面的平面移动，手脚一起走，不执行骨盆保脚；姿势/骨长/缩放不变。前后深度换视角再拖。一次拖动一步撤销，Esc/失焦取消，整体位置随姿势保存，覆盖规则不变。没有Shift快捷手势。编排预览/导出若关闭相应整体位移输出，位移可能被过滤，原始姿势不变。

1. 在当前姿势或暂停的动作画面，点击播放器“保存姿势”左侧的“编辑姿势”；进入后同位置变为“退出编辑”，视口左上显示摆姿、整体调整及撤销、重做。
2. 拖动手脚方点只摆小臂/小腿，肘膝不动，腕踝局部角度及下游跟随，不再抵消手腕朝向。超过3像素才开始编辑；目标位于观察方向的平面，前后深度换视角再拖。未映射骨架仍只支持旋转。
3. 拖动肘圆点，以肩为支点摆动上臂，前臂和手随动；拖膝以髋为支点摆动大腿，小腿和脚随动。保持原肘/膝弯曲程度和腕/踝局部姿态，直臂也能抬落；不是固定手脚调弯曲方向。只能改变指向，不能任意拉长肢体，目标在支点附近时保留上次有效姿态。
4. 拖头、颈、胸、腹、腰会联动多节脊柱，肩和手臂随躯干走；拖骨盆移动重心并尝试保留双脚位置，超出腿部可达范围则限制移动，不会拉长腿。当前仅两内置骨架支持。点击关节或从列表选择后，仍用旋转环/X/Y/Z精调掌心和虎口。没有手指预设、缩放或拉长肢体。
5. 一次拖动对应一次撤销，支持重做；Esc、指针取消、丢失捕获或窗口失焦取消当前拖动。编辑动作取帧或默认姿势后保存，输入名称新建普通自定义姿势；编辑已有自定义姿势或AI工作区姿势后保存，提示确认覆盖原姿势，不增加条目，ID、名称和库归属不变。取消覆盖保留编辑草稿，写盘失败保留原素材及草稿；AI姿势手动覆盖后标记用户保留。未进入编辑直接保存当前画面仍走新建命名流程。助手`pose.save`命令仍是新建，不受手动覆盖规则影响。
6. 点空白取消关节选择并隐藏旋转环，不改变姿势或撤销历史；重新点关节可继续旋转。退出编辑时确认放弃，取消退出保留选择，确认退出后再进入不保留上次选择；未保存草稿不跨重启恢复。骨盆保脚不是全局严格锁脚，也没有地面碰撞；其他拖动不会自动保脚。躯干每节单次手势最多约29°是数值保护，不是完整生理关节约束。必须检查肩肘腕、胸部及脚底，不能把数值正确当作无穿模。

关节点为3D场景内随人物投影变化的3–12像素小点，与骨骼线/模型同帧绘制；透明点击范围仍为16像素，网页按钮不再画点。重叠时按距离屏幕中心最近的关节点选择。手脚摆下半段、肘膝摆整肢、躯干点联动、骨盆移动，单击都可旋转；不认识的骨架不猜测联动链。标记只在编辑显示，不进入保存姿势、截图媒体和模型导出。

摆姿时先点选关节，再抓红/绿/蓝三轴圆环，分别绕关节局部X/Y/Z轴旋转。环为有截面厚度的完整圆管，前实后淡，悬停提亮当前轴、其他轴淡化；不叠自由旋转球或屏幕外圈。松手提交一步、Esc取消当前拖动，保存规则不变。点空白取消关节选择。

整体旋转不再单独切工具：“整体调整”里先点人物，骨盆附近出现世界三轴环，拖动围绕骨盆旋转整个人；根位置会同步补偿，以保持旋转中心不漂移，其他关节局部姿态与缩放不变。环命中优先，拖表面才平移，平移后环跟随人物；每次拖动各一步撤销，支持Esc/失焦取消并随姿势保存。点空白、退出编辑或切回“摆姿”隐藏整体环。未映射骨盆的模型使用选中时网格包围盒中心，不猜骨名。不会自动锁脚或防穿地。

正常编辑不显示关节名称浮标、悬停提示、右侧微调面板或微调按钮；直接在人物上拖节点、用圆环旋转。

定向验证和当前预览状态见[验证记录](verification.md)。当前不执行完整回归或发布门禁，不替换正式安装。源码复用与参考边界见[摆姿源码证据](references/fisher-pose-interaction.md)。

## 1. 先分清制作对象

| 对象 | 保存的是什么 | 不能混同于 |
| --- | --- | --- |
| 姿势草稿 | 当前完整节点变换、形态权重及编辑历史 | 已保存素材；退出/崩溃不保证恢复 |
| 姿势素材 | 属于当前模型的完整静态姿势 | 动作中的一个瞬间截图 |
| 时间轴片段 | 对素材的一次使用，以及停留/播放时长、进入过渡等 | 素材本身；删片段不删素材 |
| 自定义动作 | 保存后的完整编排，可作为成品动作使用 | 当前未保存时间轴；启动不自动恢复后者 |
| GLB | 模型和烘焙动画，用于后续使用 | 可继续逐项修改的原编排配方 |
| PNG/视频 | 可见效果的检查证据 | 工程、姿势素材或动作素材 |

制作主线：**确认实例 → 读取骨架/素材 → 草稿试摆 → 多视角检查 → 保存关键姿势 → 编排 → 连续检查 → 局部修帧 → 保存动作/导出。**

同一个姿势可放进时间轴多次，每次片段ID不同。模型切换后重新读取身份与ID，不跨模型复用`node:N`或素材ID。默认素材不覆盖；修订另存，保留原动作。

### 素材复制与粘贴

素材行聚焦后按Ctrl+C，或右键选择复制；在素材区按Ctrl+V，或右键选择“粘贴到自定义动作库/姿势库”。默认、第三方、自定义动作都可复制成自定义动作；默认和自定义姿势只能复制成自定义姿势。动作页不能粘贴姿势，姿势页不能粘贴动作；粘贴不会修改默认库，即使在默认库上操作也只新增到对应自定义库。

副本生成新ID，名称自动追加“副本”“副本 2”等，并限制在80字符内；动作内部轨道/嵌套配方、姿势完整节点快照均独立复制。复制后再改名或删除源素材不影响已复制内容。粘贴不改变时间轴和当前预览；保存失败不发布新素材，可再次粘贴重试。

剪贴板仅存在当前工作台会话，关闭/刷新后消失；已粘贴素材正常持久化。仅允许相同模型身份，不跨模型重定向，不读取/覆盖系统文字剪贴板。快捷键限定素材区，输入框仍使用系统文字复制粘贴。共享操作为`workbench.libraryClipboard.copy/paste/inspect`，属于界面应用能力，不新增外部命令；当前38条命令包含另行增加的6条工作区命令。

### 重命名操作

自定义动作与姿势行悬浮/键盘聚焦后显示铅笔按钮，或按F2打开重命名框；原名会自动选中，输入后按保存，Esc/取消不修改。默认素材不提供此入口。名称首尾空格在界面移除，非空且最多80字符；同类自定义素材重名拒绝，不覆盖另一份。保存失败在弹窗显示错误并保留原名，可修正后重试。

改名只修改库素材名称，ID、姿势快照、动作内部片段/轨道均保留；当前匹配的库预览名和正在编辑的动作标题同步。已放入时间轴的片段是独立副本，仍保留当时名称/内容，不反向修改旧编排或历史。刷新或重启后仍是新名；不必重新制作动作。该入口走共享工作台及原存储事务，38条外部命令尚无重命名操作；AI素材经人工改名会自动标记保留，不被任务整理自动回收。

## 2. 连接与请求方式

### 2.1 确认入口，不接错资料

先确认正在运行的EXE、设置里的个人数据目录、当前模型和未保存内容。个人目录不是素材库目录，也不是导出目录。正式客户端分别启用命令控制、姿势操作、编排操作；授权仅当前会话有效。隔离开发预览有默认授权例外，见[协议说明](command-control.md#开发预览默认授权)。不能用开发开关绕过正式包授权。

在仓库根目录查询（将目录替换为实际个人目录）：

```powershell
node scripts/motion-command.mjs --data-dir 'D:\实际个人目录' --operation session.inspect
node scripts/motion-command.mjs --data-dir 'D:\实际个人目录' --operation model.inspect
node scripts/motion-command.mjs --data-dir 'D:\实际个人目录' --operation library.list --offset 0 --limit 100
```

客户端内置入口为EXE旁的`MotionDeck-command.cmd`，参数相同，不要求另装Node。开发脚本使用仓库运行时环境。命令不会替你启动客户端。

### 2.2 复杂参数统一用UTF-8请求文件

例如`request.json`：

```json
{
  "operation": "pose.fromClip",
  "requestId": "pose-start-01",
  "modelKey": "<session.inspect返回的64位模型哈希>",
  "expectedRevision": 12,
  "args": {"clipId": "<library.list返回的动作ID>", "time": 0.2}
}
```

```powershell
node scripts/motion-command.mjs --data-dir 'D:\实际个人目录' --request 'D:\请求目录\request.json'
```

示例占位符必须替换，版本12只是格式示意，不能照抄。令牌/协议版本/会话由客户端附入，不读写或公开凭据文件。下文每条代码都是`args`，与表中的命令名一起放入上述请求。

所有写命令以及只读的`sequence.sample`均需当前`modelKey`和`expectedRevision`。可以使用上一条响应版本；用户操作后重新查询，不自己做版本加一。写入前暂停，避免边播放边改。成功看`ok:true`与结果，不以进程未报错推断成功。

只读分页最多100项，必须按返回`total`继续翻页；第一屏不代表全部。保存/导出要求`confirmed:true`，这代表操作者确实要执行，不能用来扩大用户授权。

## 3. 如何摆出一个姿势

### 3.1 先写动作意图，再选底姿

以起跳为例，先明确重心、脚是否接触地面、躯干倾斜、手臂方向和整体高度。选择接近目标的姿势素材，或从源动作取帧作为底姿；取现成跳跃帧只能叫复用，不能冒充手摆。

不能靠名字包含`Idle`就认定是自然站立：它也会匹配`Crouch_Idle`。先核对完整名称、实际姿势，再将它记作底姿；本手册的教学脚本明确选择Mesh2Motion的`Idle_A`，不静默换成其他待机。

1. 读取`session.inspect`、`model.inspect`、完整所需页的`rig.list`与`library.list`。
2. 用`pose.fromLibrary`或`pose.fromClip`建立草稿。修过渡用`pose.fromSequence`，不要手动只抄骨骼旋转来重建。
3. 小批修改躯干、髋膝踝、肩肘腕、头颈。通过`pose.undo/redo`比较，每批只解决一个明确问题。
4. 用`view.capture`看正面、侧面、斜侧面；看不清先改取景。必要时补局部近景，不能只看远景判断头颈或腕部。
5. 符合目标后`pose.save`，记录新ID和用途；不满意则继续或明确`pose.discard`。

### 3.2 坐标与旋转的坑

- `pose.setBones`是**局部绝对四元数**，不是角度增量或欧拉角。数组顺序为`[x,y,z,w]`，须归一化；不要给全身套单位四元数。
- 想按世界方向摆骨骼时，先求目标世界旋转，再用父骨世界旋转的逆换回局部；父骨变了要更新父链，再处理子骨。不能用修改前的父旋转转换整条新姿势。
- 保留绑定姿态的轴向补偿。骨骼Y轴不等于脸朝向；Mesh2Motion的头颈曾需要单独校正，不把旧模型角度复制给新骨架。
- 整体高度/位置用`pose.setRootTransform`，先读`model.inspect.rootTransform`。这是唯一骨架根的世界变换，不是外层场景壳。Y向上，单位随模型，不一概叫米。
- `position`是可选的骨骼局部绝对位置。取过渡帧必须保留骨盆等节点的位置，不能只抄旋转；完整取帧命令已处理快照。
- 助手命令没有IK目标求解命令、碰撞或脚底固定；未发布构建的pose.setBones已接关节范围约束，但不等于命令增加了手动拖动的求解入口。参数合法或限位通过，不能证明膝盖、肩膀或头部自然。

## 4. 如何把姿势组成动作

### 4.1 阶段、关键姿势与时间

原地跳的一条制作链：站立 → 下蹲 → 蓄力 → 蹬地 → 上升 → 最高点 → 下降 → 触地 → 缓冲 → 站稳。每阶段可有多个关键点，不要求一阶段一姿势，也不要求等时长。

先保存各姿势，再用`timeline.append`编排。下面是时间口径示意，不是自然跳跃配方：

| 片段 | 停留duration | 进入该片段的transition | 到达/停留 |
| --- | --- | --- | --- |
| 站立 | 0.2 | 0 | 0—0.2秒站立 |
| 高点 | 0 | 0.4 | 0.2—0.6秒过渡，到0.6秒立即继续 |
| 站立 | 0.2 | 0.4 | 0.6—1.0秒过渡，1.0—1.2秒站立 |

因此总时长为所有停留/播放时长加所有进入过渡；`transition`不是整段占用时长，也不是从这个片段出去的时长。以`timeline.inspect.spans`确认实际区间，别从屏幕像素推算时间。

### 4.2 连续关键姿势与普通片段

跳跃中间关键姿势推荐显式`interpolation:"continuous"`并`duration:0`，用`transition`控制到达时间。相邻两姿势都需连续标记；正停留、硬切或普通动作会分开连续段。第一项单独添加时需正时长，不能建立总长为0的非空轴。

普通姿势最短停留0.05秒，连续姿势可为0；连续姿势的正停留仍会真正停住。不能将大量0.05秒小停留当成连续关键帧。连续采样共享切线，但不保证恒定角速度、物理抛物线或接触约束。保存使用格式3，旧公开客户端不支持该资料，勿拿正式资料试兼容。

节奏应服务动作：下沉可慢、蹬地快、最高点只瞬时换向、触地到缓冲快、回站可稍慢。不是把所有段拉长就自然，也不是给每段缓入缓出就连贯。

### 4.3 手臂与位移

大臂、前臂分别设计，保留肘部弯曲；蓄力后摆、蹬地向前上摆、上升举高、下降回收与落地平衡不能整段复用一个姿势。本次用户期望跳时手臂抬到头顶上方，需在实际多视角画面确认，不只看肩部角度。

原地跳保持水平根位置，仍要有竖直高度；位移跳复用姿势，再给各关键点设置水平位置与高度。GLB默认保留全部根位移，可按下一节显式关闭对应方向，但不自动生成游戏控制器位移。先做对一个版本，再派生变体，不重复手摆两套骨骼。

### 4.4 游戏驱动位置时，关闭输出位移

视口工具栏“位移”提供水平（世界X/Z）与纵向（世界Y）两个开关，默认均开启。关闭一项将唯一根骨在该方向的位置固定为动作第0秒的世界位置，而非清零；根朝向、缩放和其他骨骼的局部运动不变。使用当前采样姿势的父链换算，不能简单把根骨局部Y设为0。非唯一根或奇异父变换明确拒绝过滤，保留全部模式不受此限制。

四种组合分别为保留全部、仅保留水平、仅保留纵向、去除全部整体位移。源动作、自定义动作及当前编排预览、参考录制、命令截图/视频/轨迹查询采用相同策略；基准始终是整段第0秒，截取后半段录像不重新以录像起点归零。静态姿势没有随时间变化的位移，单独预览不改变它。切换模型和重启默认恢复保留全部。

素材导出弹窗提供同样两个开关，打开时继承当前预览，可为这次导出另选；姿势静态导出不应用位移过滤。命令`export.glb`可显式传`rootMotion`覆盖，仅影响该次文件，省略则继承预览。多动作导出各自用自己的第0秒为基准。

**过滤只影响输出，不写素材和动作配方。** `pose.fromClip`、`pose.fromSequence`和保存姿势仍取原始姿势，不将去位移画面反存为制作源；保存自定义动作也保留原始配方。关闭升降后单独看腾空姿势可能像悬着，需要配合游戏的角色高度、腾空用时与落地事件检查；这里不含游戏控制器、水平轨道剥离数据或自动触地同步。

## 5. 如何检查，什么才算通过

### 5.1 三层验收不能互相替代

| 层次 | 做什么 | 能得出的结论 |
| --- | --- | --- |
| 工程闭环 | 命令、版本、撤销、保存、真实文件回读、状态恢复 | 操作链可执行，非动作自然 |
| 连续数值 | 等间隔骨骼位置/旋转、阶段边界前后速度、接触段误差 | 找异常候选，非网格脚底无穿透 |
| 可见动作 | 多视角全身、过渡细查、连续视频实际播放 | 判断穿插、节奏、重心和自然度，记录用户反馈 |

每项记“通过／未通过／未能验证”，附模型、阶段/时刻、证据和下一步。缺镜头、缺连续视频或被裁切就是未能验证，不能推定通过。

### 5.2 先粗查，再加密

1. `timeline.inspect`核对阶段与停留，保存当前播放头和状态。
2. `view.captureSequence`选代表性时刻、多视角看全身；用`framing:"motion"`固定比较镜头，`ground:true`看地面参照。
3. 关键姿势之间检查起点、中点、终点，以及端点前后短间隔。问题集中在0.3—0.5秒，就加密这段，不机械“一秒一张”。
4. `sequence.sample`对根、脚掌、腕等少量骨骼等间隔采样。`v≈(p下一帧-p当前帧)/Δt`，角速度用四元数最短夹角除时间；不同阶段快慢合理，但不应无意停住/突跳。不要将整份骨架每帧输出到聊天。
5. `export.video`输出连续画面，核对真实时长、解码帧数和动态帧，再实际播放判断。稀疏抽图不能推翻用户“一顿一顿”的反馈。
6. 检查后比较模型、版本、播放头、播放状态与可见姿势是否恢复；保存/插入等编辑本身当然会改变版本。

区分三种顿挫：姿势片段的真实停留、过渡两侧速度断层、播放/录制掉帧。最高点瞬时零速正常，停成一段不一定正常。视频是实时捕获，取样次数不等于解码帧数；目标30fps不承诺恒定30fps。命令录像已经适配后台/最小化，不需要激活窗口。

脚骨世界高度只能当指标，骨骼原点不一定是网格脚底。网格穿地、脚滑与足部旋转仍须看图/视频。地面网格只是参照，不是碰撞面。`pose`逐帧居中会掩盖整体位移，检查轨迹用固定镜头或世界坐标。

### 5.3 修过渡的闭环

例如问题在0.4秒，且这个时刻位于进入姿势的过渡内部：

1. `pose.fromSequence({"time":0.4})`完整取当前帧。
2. 修改骨骼/根位置；截图检查脚、头颈和手臂；另存修正姿势。
3. `timeline.insertPoseAt({"time":0.4,"poseId":"新姿势ID"})`拆分原过渡，总长不变，新点无停留，一步可撤销。
4. 重查该点左右区间，以及相邻过渡；共享切线可能影响邻段。记录前后误差，再决定是否细分。

不在停留、源动作内部或过渡端点调用插入。端点本身有错先另存修正端点。插入不会自动把原普通邻居改为连续，必须核对原配方。一个中点没完全修好不代表迭代方法无效，但无限增加姿势也不是严格锁脚；达到收益瓶颈应说明能力缺口。

已有跳跃案例从10个点迭代到27个点，总长仍2.18秒；接触段最大脚位误差从约0.152降至0.00333模型单位。这只是该模型的实测残差，不是通用阈值，不等于严格网格无穿透或整体自然度已通过。

三类媒体的`options`：width320—1920（默认1280），height240—1080（默认720），ground/skeleton默认false，framing默认motion。视角为front/right/front-right/back/left/front-left，每次最多3个不同值，视频单个view默认front-right。

## 7. 每个命令的实际使用证据

仓库提供[隔离命令示例脚本](../scripts/examples/motion-command-workflow.mjs)，复用现有命令客户端；Playwright只负责启动/关闭独立验收进程，所有业务行为通过命令完成，不点按钮、不修改渲染对象、不读取令牌。脚本每次新建`output/command-handbook/run-*/personal`资料，不连接现有预览，不复制用户数据。

```powershell
node scripts/examples/motion-command-workflow.mjs --exe 'D:\实际验收包\MotionDeckAcceptance.exe'
```

前提：仓库开发依赖已就绪、当前协议的验收包、默认Mesh2Motion模型含Idle_A、ffprobe.exe/ffmpeg.exe在PATH或设置`FFMPEG_BIN`目录。只接受验收EXE名称；自动授权仍由客户端真实身份和隔离条件核对。它新增教学姿势/动作并保留在自己的资料目录，结束关闭自己的窗口，不删除数据，不替换用户入口。

脚本实际操作：读取/分页 → 待机取帧 → 小角度试改/撤销/重做 → 截图/保存 → 库取帧/放弃 → 根高度另存 → 三点连续编排 → 过渡取帧/插入 → 时长/过渡/动作裁剪/移动/删除 → 播放 → 轨迹/批量图片/视频 → 保存动作/GLB → 查请求状态。最终将调用覆盖与协议白名单比对，遗漏任何一个命令即失败。

证据在本次`output/command-handbook/run-*/proof.json`：实际请求/回复、当前白名单命令覆盖、模型/版本、资料路径、PNG/索引/视频/GLB路径和媒体回读结果。`calls.json`即使中途失败也保留已执行记录；本次目录没有最终proof不能声称全部通过，不能拿上次报告顶替。GLB解析检查动画/位置轨道，PNG检查尺寸/摘要，视频解码检查帧数/动态帧，并验证采样/媒体操作恢复状态。完整请求记录可直接对照各命令示例；其中身份/版本/ID仍只属于那次隔离实例，不能复制到用户当前窗口。旧31条报告不包含后来新增的位移策略命令，需看本次实际covered数量。

这是**命令闭环教学夹具**，只是站立抬高再落回的示意，不是手摆自然跳跃质量验收，也不代替用户正式安装升级检查。输出默认忽略、不进Git；每次运行的资料、调用与报告在同一独立目录。

## 8. 错误、恢复与交付清单

| 现象 | 正确处理 |
| --- | --- |
| NO_INSTANCE / SESSION_CLOSED | 确认EXE、实际个人目录和控制启用状态；不要自动启动另一个空实例 |
| AUTH_FAILED / WRITE_DISABLED | 按设置确认本次授权，不改凭据/权限绕过 |
| NOT_READY / BUSY | 等当前加载/长操作完成，查状态；有草稿先决定保存或放弃，别连发写请求 |
| MODEL_MISMATCH / REVISION_CONFLICT | 重读模型、轴和草稿，对照制作记录；不要自动重放旧写入 |
| INVALID_ARGUMENT / UNSUPPORTED_RIG / LIMIT_EXCEEDED | 核对坐标、ID、范围、归一化和数量预算；不静默换骨架/旧实现 |
| DUPLICATE_NAME | 核对是否已保存；明确版本名另存，不删除原素材 |
| RESULT_UNKNOWN | 保留原requestId查request.status，再核对库/轴；不能换号重复保存/导出 |
| REQUEST_ID_CONFLICT | 同编号的内容已不同；先厘清原请求，不能用去重缓存当重试万能钥匙 |

普通查询预算10秒，写入/单帧30秒，批量截图与视频90秒。去重最多本次会话256条，不保证跨重启恰好一次。pending等结果；unknown不是执行失败或未执行的证明。媒体长任务期间只用状态查询跟踪，不排入大量渲染请求。

每轮交付至少留下：模型身份；姿势素材ID与轴片段ID的对应；每段停留、过渡及连续标记；原版本与修订版本；截图时间索引/视频/GLB路径；逐项通过/未通过/未能验证；未保存内容和下一步。不要保存令牌，也不重复输出整份骨架。
